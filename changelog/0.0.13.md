# 0.0.13 - Relations & authorization

_2026-09-24_

The **relations-and-authorization release.** The ORM learned to walk relations as a first-class, chainable path - `post.author().await?`, `user.developer().software_groups().software().fetch().await?` - all served from the `select_related` / `prefetch_related` cache with zero extra queries, plus multi-hop aggregates and `__` traversal on the filter side. Alongside it: **materialized computed fields** that recompute themselves when their sources change, **object-level (IDOR) authorization** with a boot check that fails a deploy leaving a write surface unscoped, **cache-first role-aware media access**, and **signals + audit on transactional writes**. A large developer-ergonomics batch (`#[umbral::main]`, `#[model(base = …)]`, `#[derive(New)]`, `umbral plugin add`, `umbral doctor`) and an admin redesign round it out.

Versions follow [Semantic Versioning](https://semver.org/); the sections below follow [Keep a Changelog](https://keepachangelog.com/) (Added / Changed / Deprecated / Removed / Fixed / Security). For the exact per-crate bullet history these are distilled from, see each crate's own `CHANGELOG.md`.

## Highlights

- **Chainable relation traversal.** Read a related object through an awaited accessor - `post.author().await?` (or `.get_opt().await?` when it may be absent), `post.tags().fetch().await?` for a to-many - and chain across kinds to the leaf: `user.developer().software_groups().software().fetch().await?`. Every hop composes into one JOIN / `IN`-subquery chain, is deduplicated by primary key (`.with_duplicates()` to opt out), and is served from the `select_related` / `prefetch_related` cache with **zero further queries** once populated. **This replaces the removed `.resolved()` reader (see Removed).**
- **Materialized computed fields.** A column on one model can be declared *materialized*; the framework recomputes and writes it back automatically whenever a declared source table changes - `App::builder().materialize(Materialized::<Order>::new()...)`. The dependency is expressed at one site and never goes silently stale; refresh fires on per-row *and* set-based bulk source updates, with a re-entrancy guard and boot-time validation of the declarations.
- **Object-level (IDOR) authorization.** A boot-time system check flags any auto-exposed *writable* model that has no object scope across REST, GraphQL, and storage, so an unscoped write surface fails the deploy instead of leaking cross-tenant rows. Opt into strictness with `strict_object_scope` (`UMBRAL_STRICT_OBJECT_SCOPE`), scope writes with `owned_by_for_writes` / action-aware scopes / a declarative relation-path owner scope, and acknowledge a deliberate exception with `unscoped_ok(reason)` / `rls_backed()`.
- **Cache-first, role-aware media access.** `StoragePlugin::media_access_cached(|MediaCaller, key| -> Decision)` gates who can fetch an uploaded file, with a framework-owned per-caller cache key checked *before* your DB closure; `media_access_staff` / `media_access_roles` presets and `media_invalidate_on::<M>` signal-driven busting. Built on a new cross-plugin **`TaggedCache`** contract with `bust_tag` across the memory, SQLite, and Redis backends.
- **Signals on transactional writes.** Writes made through `on_tx()` inside `db::transaction*` now emit their `post_save` / `post_delete` / `bulk_*` signals **and** the audit-log entry after the transaction commits (never on rollback) - closing a gap where deployed apps silently missed signals on transactional writes.

## Added

- **Chainable relation accessors, generated per model** - forward FK/O2O, reverse FK, reverse O2O, and M2M, each returning a `Relation<T>` or a chainable `QuerySet<T>` you can keep filtering. `Relation` is re-exported from the facade.
- **Multi-hop aggregates over relation paths** - `annotate` / `aggregate` across `__`-joined relation paths, with intermediate-hop soft-delete scoping.
- **Forward FK/O2O `__` traversal on the filter side** - filter and order by a related model's columns without a manual join.
- **`prefetch_map`** - batched reverse-FK loading with no declared field on the parent, and cache-aware to-one / to-many accessors that serve `select_related` / `prefetch_related` with zero queries.
- **Materialized computed fields** - `AppBuilder::materialize`, the `Materialized<M>` builder (type-erased), `DynQuerySet::filter_pk_eq` for generic-PK single-row refresh, and boot-time validation of every materialized declaration.
- **Object-level authorization surface** - `owned_by_for_writes`, action-aware object scopes, a declarative relation-path owner scope, `strict_object_scope` (`SystemCheck` now carries an owned closure), and the `security.object_scope` boot check with `unscoped_ok` / `rls_backed` acknowledgement markers.
- **`TaggedCache` cross-plugin caching contract** - object-safe `umbral::cache::TaggedCache` in core, with tagged `get_or_compute` + `bust_tag` across memory, SQLite, and Redis (each with a pruned tag index).
- **Developer ergonomics** - `#[umbral::main]` + `umbral::Result` (a one-line entrypoint), `#[model(base = A, B, …)]` multi-base composition, auto-`Default`/`new()` on `#[derive(ModelBase)]`, `#[derive(New)]` partial insert shapes with `impl Into<T>` on `create`, `#[umbral(str = "{a} {b}")]` per-instance display templates (a model `__str__`), and typed column names via `.name()` / `AsRef<str>` / `Display`.
- **CLI** - `umbral plugin add`, a unified `umbral help` / `--help` / `--version` catalog (including plugin- and project-contributed commands), `umbral doctor` for pre-deploy diagnostics, an `umbral::sqlx` re-export, and `startproject` now scaffolds a Cargo workspace with `[workspace.dependencies]`.
- **REST / OpenAPI** - `action_by` natural-key detail actions, read-side `?expand` for reverse-FK and M2M relations, and validation responses that return **all** field errors at once instead of the first.
- **Nested writes outside REST** - a reusable nested-tree writer (`umbral::orm::nested`, create + update reconciliation) callable from any code, not just the REST layer, plus synchronous in-transaction after-create hooks.
- **Email** - a pluggable `EmailBackend` trait (`EmailPlugin::with_backend`) so you can bring your own sender, and task-backed / `umbral-email`-delegating auth mailers.
- **Admin redesign** - the changelist reads as a table editor with drag-resizable columns, a cleaner record form and detail read-view, a tokenized form/detail layer, an aligned shell with visible active-nav, dashboard labels that match the rest of the admin, and the cool-slate *umbra dusk* theme.
- **Core** - a middleware registry (introspect the active middleware by plugin and order) and model-level presentation/query metadata shared across plugins.
- **Auth** - the password-reset link path is now operator-configurable (`AuthPlugin::reset_path`) and honours `settings.app_url`.

## Changed

- **REST validation returns every field error at once** (`validation_error`, flat per-field arrays + `non_field_errors`) rather than stopping at the first.
- **Postgres M2M junction ids bind by the referenced primary-key type**, not the JSON shape, so non-`i64` M2M targets write correctly.
- **`auto_user`** freezes `auto_user_add` and refreshes `auto_user` on a typed `UPDATE` (matching the create-path contract).
- Generated column-token modules inherit their model's visibility.
- Documentation: a full accuracy sweep of the `v0.0.1` docs against the code (39 pages).

## Removed

- **`.resolved()` - breaking.** The ergonomic `.resolved()` reader on `ForeignKey<T>`, `OneToOne<T>`, `M2M<T>`, and `ReverseSet<T>` is gone. Read related objects through the awaited accessor instead (`post.author().await?`, `.get_opt().await?`, `post.tags().fetch().await?`), which is served from the same cache with zero extra queries.
- **`startapp` - breaking.** The deprecated `startapp` command (and `scaffold_app`) is removed; use `startplugin`.
- **`Op` comparison enum - breaking.** Retired in favour of `Cmp` / typed column comparisons.

## Fixed

- **ORM relations** - reverse-FK and reverse-O2O accessors are chain-composable; a junction join never goes `RIGHT` under an M2M `walk_joins` hop; deep to-many chains error (not panic) and poison the query rather than misbehave; the poison/`DISTINCT` contract is enforced on `_pg` terminals and on write/scan terminals; ambiguous reverse resolution panics loudly instead of guessing.
- **`filter_annotation`** - honours `limit` / `offset` and re-applies `ORDER BY` on the outer wrap (Postgres correctness); deep-hop soft-delete and the decode-path resolver were de-duplicated.
- **Signals** - `signal_skip` fields are redacted from full-row `post_delete` payloads; typed `QuerySet::delete()` and `DynQuerySet::delete()` fire a per-row `post_delete` carrying the full row when a subscriber exists (PK-only otherwise).
- **Caching** - injective media-access cache key (length-prefixed, no `:`-collisions), a guard against a bust write-skew between a cache miss and its store, SQLite/Redis tag-index pruning on delete/clear/retag, and a bounded `BustLog`.
- **Migrations** - SQLite rebuild-drops constrained columns; `auto_now` is stamped on typed updates.
- **Nested writes** - collect and drill down validation errors by path; FK-target models derive `Clone`.
- **CLI** - a bare `help` after a scaffold command shows help (not a plugin), and scaffolders dispatch from the app-embedded CLI too.
- **Admin** - search-as-you-type replaces history instead of pushing it, and datatable row fragments use a deterministic reflected nav URL.

## Security

- **Object-level write-surface boot check** - flags auto-exposed writable models (REST / GraphQL / storage) that lack an object scope, so an IDOR-prone surface is caught at boot rather than in production.
- **OAuth** - SPA-login ergonomics plus boot-time safety checks that reject an unsafe social-login configuration.
- **Transactions** - the `on_tx()` audit insert is wrapped in a savepoint so a failed audit row can't poison the caller's Postgres transaction.
