# gaps6

1. [ ] **Field-name → `&str` from the model, typo-safe + autocompleted** — the user hand-types column-name string literals (`"username"`) in many places (`select_related`, `values`, `order_by`, `search_fields`, ad-hoc lookups), which is error-prone. Ask: `AuthUser::USERNAME` should yield the `&'static str` `"username"` so a mistyped field is a compile error and the editor autocompletes it.

    **Constraint:** `Model::USERNAME` is *already* taken — `#[derive(Model)]` emits it as a typed **column token** (`pub const USERNAME: <Col>Col<Model>`, see `crates/umbral-macros/src/lib.rs:272`) used for `.eq()` / `.to()` / `.order_by()`. It cannot simultaneously *be* a bare `&str` (associated-const name collision). So the design is to expose the name **off the existing token**, not to redefine `Model::USERNAME`.

    **Recommended design:** give the column token a `pub const fn name(&self) -> &'static str` **and** an `AsRef<str>` / `Display` impl, so `User::USERNAME.name()` returns `"username"` and the token can be passed anywhere a `&str` / `impl Into<String>` column name is accepted (e.g. `select_related`, `values(&[...])`). This preserves autocomplete (you type `User::` and see every field) and makes a typo a compile error. Alternative if a bare-const form is wanted: a sibling lowercase module already exists (`user::NAME`, `session::ID` are also typed column tokens) — do NOT add a colliding string const there; prefer the `.name()` method on the one token type.

    **Scope:** `crates/umbral-macros/src/lib.rs` (emit `name()` / `AsRef<str>` on the generated `Col` type — likely once on the generic `Col<M>` in `umbral-core`, not per field), `crates/umbral-core/src/orm/` (the `Col` type), a re-export check in the facade, one behavioral test (`User::USERNAME.name() == "username"` and a `select_related`/`values` call driven by the token), and a short `documentation/docs/v0.0.1/orm/` note. Small, self-contained; **orthogonal to the ORM heavy-relations epic** (`docs/specs/orm-heavy-relations-epic.md`) — that epic is the relation→JOIN engine, this is scalar field-name metadata. Can be picked up independently.
